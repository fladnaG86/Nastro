# Nastro Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** App macOS da barra dei menu che registra schermo + audio di sistema + microfono (o solo audio) in un file `.mp4`/`.m4a` con una sola traccia audio.

**Architecture:** ScreenCaptureKit consegna tre flussi di campioni; `MovieWriter` li scrive con `AVAssetWriter` in un file di lavoro `.mov` a frammenti (due tracce audio separate); a fine registrazione `Finalizer` copia il video senza ricodifica e fonde l'audio nel file definitivo. La logica pura sta in `NastroCore`, la parte AVFoundation testabile in `NastroMedia`, cattura e interfaccia nell'eseguibile `Nastro`.

**Tech Stack:** Swift (swift-tools-version 5.9, toolchain 6.4), Swift Package Manager, ScreenCaptureKit, AVFoundation, SwiftUI `MenuBarExtra`, Carbon (scorciatoia), UserNotifications, XCTest.

**Spec:** `docs/superpowers/specs/2026-11-17-nastro-design.md`

## Review Focus

1. Microfono con formato diverso da 48 kHz stereo (AirPods: 16 o 24 kHz mono): la voce deve essere registrata alla velocità giusta. → test in Task 4.
2. Schermo fermo: ScreenCaptureKit non manda fotogrammi se nulla cambia; il video deve durare quanto l'audio, non fermarsi all'ultimo cambiamento. → test in Task 4.
3. Stop immediato dopo lo start, prima che arrivi un campione: nessun crash, nessun file vuoto lasciato, stato che torna a riposo. → test in Task 4 e Task 3.
4. Cartella di destinazione inesistente o non scrivibile (disco esterno scollegato): errore chiaro all'avvio, nessuna registrazione fantasma. → test in Task 2.
5. File di lavoro da recuperare vuoto o illeggibile: non deve far fallire l'avvio né essere ritentato a ogni lancio. → test in Task 5.

Transizioni valide (tutte le altre restituiscono `false` e non cambiano stato):
`idle —startRequested→ starting`; `starting —started→ recording`; `starting —startFailed→ idle`; `starting —stopRequested→ finalizing`; `recording —stopRequested→ finalizing`; `finalizing —finalized|finalizeFailed→ idle`.

**Interfaces:**

- Produces:

```swift
public enum WriteResult: Equatable, Sendable { case written(duration: Double), empty }
public final class MovieWriter: @unchecked Sendable {
    /// video == nil → solo audio. Crea il file in `url` (.mov).
    public init(url: URL, video: VideoSpec?, systemAudio: Bool, microphone: Bool) throws
    /// Chiamabile da qualsiasi thread; serializza internamente.
    public func append(_ kind: SampleKind, _ buffer: CMSampleBuffer)
    /// Chiude il file. `.empty` (e file cancellato) se non è mai arrivato un campione.
    public func finish() async throws -> WriteResult
    public var failure: Error? { get }     // primo errore di scrittura, se c'è stato
}
```

- Produces (solo test): `TestMedia.videoFrame(width:height:at:) -> CMSampleBuffer` (BGRA, colore pieno), `TestMedia.tone(sampleRate:channels:at:duration:) -> CMSampleBuffer` (PCM float, sinusoide 440 Hz ampiezza 0.5), `TestMedia.tracks(of: URL) async throws -> (video: Int, audio: Int, duration: Double)`, `TestMedia.audioFormats(of: URL) async throws -> [(sampleRate: Double, channels: Int)]`.

Decisioni fissate:
- `AVAssetWriter(fileType: .mov)`, `movieFragmentInterval = 10 s`, `initialMovieFragmentInterval = 2 s`.
- Video: HEVC, `AVVideoAverageBitRateKey = width × height × fps × 0.05`, `expectsMediaDataInRealTime = true`.
- Audio: un `AVAssetWriterInput` per sorgente, AAC. Il formato (frequenza, canali) si legge dal **primo campione** di quella sorgente e l'input si crea in quel momento; mai valori fissi. Bitrate 128 kb/s per due canali, 64 kb/s per uno. L'ordine delle tracce nel file non è garantito: `Finalizer` non deve dipenderne.
- La sessione parte (`startSession(atSourceTime:)`) al tempo del primo campione accettato: in modalità video il primo fotogramma (i campioni audio precedenti si scartano), in solo audio il primo campione audio.
- Poiché gli input audio nascono al primo campione ma `AVAssetWriter` non accetta nuovi input dopo `startWriting`, il writer tiene in coda i campioni finché tutte le sorgenti attese hanno mostrato il formato **oppure** sono passati 2 s dal primo campione; le sorgenti che non si sono presentate entro 2 s restano senza traccia.
- Schermo fermo: a `finish()` in modalità video, se l'ultimo fotogramma è più vecchio dell'ultimo campione audio, si riscrive l'ultimo fotogramma con il tempo dell'ultimo campione audio, così il video dura quanto l'audio.
- Un campione rifiutato perché l'input non è pronto si scarta (mai bloccare il thread di cattura). Un errore del writer si salva in `failure` e i campioni successivi si ignorano.
